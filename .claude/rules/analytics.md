# Analytics

- `analytics` — a `*.json` singleton switchboard: per-provider `{enabled, id}` (PostHog, Umami, GA4, Meta Pixel, Clarity, GTM) + a `consentBanner` toggle. `src/lib/analytics.ts` (`getAnalytics`) resolves it to per-provider `active` (enabled **and** id non-empty) plus flags (`anyCookieProvider`, `needsConsentBanner`, `misconfigured` → build-time `console.warn`). `Analytics.astro` (mounted in `BaseLayout` `<head>`) injects each provider's script **only when active**, all as `is:inline` so the gating actually holds (bundled `<script>` can't be conditional); default all-off ⇒ zero analytics scripts. Cookie providers are consent-gated (Google via Consent Mode v2 default-denied; Pixel/Clarity deferred until the `bb:consent-granted` event from `ConsentBanner.astro`); PostHog and Umami run cookieless. Interaction tracking is an inline event layer that fans one event out to PostHog + `dataLayer`, driven by `data-track` / `data-track-*` attributes on elements (WA "Donasi" click = the conversion). **`donate_click` and `inquiry_click` both survive and are now selected by `aksi.mechanism.kind` in `Ajakan.astro`, not by a hardcoded list of programme slugs** — `quantity` fires `donate_click`, `conversation` fires `inquiry_click`. Keeping both names was deliberate: they are the conversion definitions, and collapsing them would have broken the historical series at the point where the mechanism became content. `aksi_click` is the third, fired by the "cara ikut" buttons on the pintu pages, carrying `data-track-source="pintu_<id>"` and the aksi title). Provider IDs are public client-side keys, safe in the repo. See `openspec/changes/add-analytics-tooling/`.
