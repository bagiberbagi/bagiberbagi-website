# Image Pipeline

- **Jejak photos live in `src/assets/jejak/`, not `public/uploads/`.** Only files under `src/` go through `astro:assets` (webp conversion, multiple widths, intrinsic dimensions for `<Image>`), and raw field photos run one to two megabytes each, which would sink `/jejak/` as documentation accumulates. Keystatic uploads there with `publicPath: '/src/assets/jejak/'`, matching exactly the key shape of the eager `import.meta.glob` in `src/lib/jejak.ts` that maps the stored string back to an image module; change one side without the other and every photo resolves to null. A missing file warns at build and falls back to a pintu icon rather than failing the build, because one stale path should not take the whole site down. **Deduplicating those modules must use object identity, never a property read like `img.src`**: Astro proxies image modules and marks the source file as "used directly" the moment any property is read outside the image pipeline, which copies the raw PNG into `dist/` and throws away the entire optimization. Cheap check after a build: `find dist/_astro dist/uploads -iname '*.png' | wc -l` must print 0. The `/jejak/` gallery also pre-builds a separate large webp per photo with `getImage()` for the lightbox, so opening one never fetches a thumbnail's multi-megabyte source. Program photos follow the same route: Keystatic uploads them to `src/assets/programs/` with `publicPath: '/src/assets/programs/'`, matching the eager glob behind `resolveProgramImage` in `src/lib/programs.ts`, so they are `astro:assets` modules too. They have to be, since `ProgramStage.astro` puts them in a full-bleed 78vh band, not only in a card.
