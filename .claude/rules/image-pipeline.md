# Image Pipeline

- **Jejak photos live in `src/assets/jejak/`, not `public/uploads/`.** Only files under `src/` go through `astro:assets` (webp conversion, multiple widths, intrinsic dimensions for `<Image>`), and raw field photos run one to two megabytes each, which would sink `/jejak/` as documentation accumulates. Keystatic uploads there with `publicPath: '/src/assets/jejak/'`, matching the key shape of the eager `import.meta.glob` in `src/lib/jejak.ts` that maps the stored string back to an image module; change one side without the other and every photo resolves to null. **That glob must stay recursive.** Keystatic writes flat only while `fields.image` sits at the top level of an entry; once it is nested inside `fields.object` or `fields.array` it names the file after the entry slug plus the field path, so `cover` and `gallery` now arrive as `/src/assets/jejak/<slug>/cover/image.jpeg`. Both shapes exist in the repo today and the recursive pattern matches both. `programs` and `organisasi` are unaffected only because their image fields are still top-level; nest either one and the same silent failure appears there. A missing file warns at build and falls back to a pintu icon rather than failing the build, because one stale path should not take the whole site down. **Deduplicating those modules must use object identity, never a property read like `img.src`**: Astro proxies image modules and marks the source file as "used directly" the moment any property is read outside the image pipeline, which copies the raw PNG into `dist/` and throws away the entire optimization. Check after a build with `bun run check:assets`, which fails when `dist` carries an image no page references. It replaced `find dist/_astro dist/uploads -iname '*.png' | wc -l`, which had two holes: it only counted PNG while 22 of 24 jejak sources are jpg or jpeg, and it flagged by extension, so the jpeg poster `jejak/[slug].astro` builds on purpose for the JSON-LD `thumbnailUrl` would have to be excepted. **The mechanism that produces a leak:** `import.meta.glob` with `eager: true` statically imports every match and Vite emits an asset per import, so a photo rendered through `<Image>` is replaced by its optimised variants while a photo imported but never rendered lands whole. The moment content stops pointing at a file still on disk, its full-size original starts shipping. That is not hypothetical: on 10 August 2026 the Keystatic admin dropped nine `image:` lines from one entry on save, which cost that published page all its photos and started shipping 7.7 MB of unreferenced originals, with the old check still printing 0. A jejak photo is a `JejakPhoto` (`{img, alt, caption}`), not a bare module, so dedup keys on `photo.img` — a property of the wrapper, which is safe, unlike a read on the module itself. That dedup lives in one place, `dedupePhotos()` in `jejak.ts`, and it is **first-wins**: a file may be both a cover and a gallery entry carrying different descriptions, and `new Map(pairs)` would keep the cover's position but the gallery entry's text, silently discarding an alt the editor wrote. The `/jejak/` gallery also pre-builds a separate large webp per photo with `getImage()` for the lightbox, so opening one never fetches a thumbnail's multi-megabyte source. Program photos follow the same route: Keystatic uploads them to `src/assets/programs/` with `publicPath: '/src/assets/programs/'`, matching the eager glob behind `resolveProgramImage` in `src/lib/programs.ts`, so they are `astro:assets` modules too. They have to be, since `ProgramStage.astro` puts them in a full-bleed 78vh band, not only in a card.
