# Routing & Taxonomy

- `src/pages/index.astro` assembles the beranda from one component per section (`Hero` + `Stats` sharing one photo zone, then `ProgramFeatures`, `ProgramHighlights`, `HowItWorks`, `ImpactSection`, `FaqHome`, `JoinUs`, `PintuSection`). `JejakTerbaru.astro` is finished and wired but its import is commented out on purpose: the showcase lives at `/jejak/` until the home design catches up.
- `src/consts.ts` holds small structured UI data as plain typed arrays/objects: `FEATURES`, `STEPS`, `IMPACTS`, `NAV_LINKS`, `PINTU_IDS`/`PINTU`/`PINTU_LABEL`, `CATEGORY_CONTENT`, plus the `IconName` and `ProgramMenuCategoryData` types. Deliberately not a Content Collection, since these are fixed-size, tightly coupled to one section each, and never individually routed. Editor-managed prose/data lives in `src/content/` instead (see `content-model.md`).
  - `NAV_LINKS` is four items (Pintu Berbagi, Jejak & Dampak, Tentang Kami, FAQ), ordered along the donor's trust path. No "Home" because the logo is the way back, and no "Cara Kerja" because the version that actually helps differs per program, so it lives on the program page with a secondary link from the Hero. The `program` entry renders as the mega-menu trigger, not a link, so its `href` is only a fallback.
  - **`PINTU_IDS` is the single source of the pintu taxonomy, and its axis is PERUNTUKAN — what changes for the recipient, not what the giver hands over.** The six ids are `food`, `education`, `health`, `empowerment`, `humanitarian`, `environment`; ids are English and slugs Indonesian, and `food` survived the axis change because in English it covers food security. Form of contribution (goods, time, space, money) is no longer a taxonomy at all: it lives in `aksi` items and their mechanism, and the two that had real content became site-level pages (`/relawan/`, `/logistik/`). **A programme declares several pintu (`pintu[]`) plus one `pintuUtama` that owns its card, breadcrumb and — critically — its numbers; `getPintuImpact` filters on `pintuUtama` alone, or one jejak's metrics would be counted once per pintu its programme claims.** `PintuId`, the zod enum in `content.config.ts`, and the Keystatic select options all derive from it, so adding or removing a pintu is a `consts.ts`-only edit. Each `PINTU` entry also carries its identity color trio (`color`/`colorTint`/`colorDeep`), fed to markup as the `--cat` CSS var, so no consumer hardcodes a pintu color.
  - `CATEGORY_CONTENT` is the conceptual copy for the pintu landing pages (story, stats, how-it-works, for-whom, env, FAQ, CTA), still hardcoded. Every block is optional and an empty one is not rendered, so only `food` and `environment` are filled — the latter inheriting the story written for the retired Pohon door — and the other four pintu pages render lean but tidy. **`contribute` used to be one of those blocks and is the one that left**, into the `aksi` collection (see `content-model.md`); the rest stayed. The reason only that one moved is worth keeping: every other block is prose a reader looks at, while `contribute` was a list of *ways to take part* rendered as inert numbered text, claiming a mechanism it did not have. Moving it is what let each item carry a real destination.
  - **The pintu page has an empty state again, and this is the first time it can actually happen.** `showForms` (the `#bentuk` section fed by `PINTU_CONCEPT[*].examples`) and `joinAsSteps` (the join block falling back to `id="alur"` with the generic intake flow) both test whether the pintu has any aksi to show. While `contribute` was hardcoded and all six pintu were full, neither branch could ever execute; now that an editor owns the list, both can. They were kept rather than deleted for exactly that reason — a guard was about to start firing for the first time.
- Routes live in `src/pages/` under an "entity = pintu (kategori) → program → jejak" information architecture. **Pintu is the primary taxonomy and owns pages** (`/peduli/` is a real hub, and `/peduli/<slug>/` nests under it). **This reverses an earlier decision, deliberately.** Pintu used to be a filter sitting beside programme, so a hub would have been a page with nothing to say; once pintu carried the main navigation that premise expired. The hub also retires a workaround — `/peduli/<slug>/` derives its breadcrumb from the URL, which programme pages cannot do because `/program/` is only a redirect stub: pintu surfaces via home `PintuSection`, the mega-menu, colored badges, and the `?peduli=<pintu-slug>` filter on `/jejak/` (which still reads the old `?berbagi=` name so shared links keep their filter). Pages: `index`; `faq`; `tentang`; **program detail** `program/[program].astro` (`/program/<slug>/`, dynamic from `getProgramPages()`, so activating a program in Keystatic + filling its `detail` generates the page with no new file; bare `/program` redirects to `/#pintu` via `astro.config`; on a static build that redirect ships as a noindex meta-refresh stub, not an HTTP 30x, which is why programme pages must declare `breadcrumbTrail` rather than let the crumb be derived from the URL — the derived one names `/program/` and that page does not really exist); **pintu hub** `peduli/index.astro` (`/peduli/`, six doors with a status derived from programme data, plus the links to `/relawan/` and `/logistik/`); **pintu landing** `peduli/[pintu].astro` (`/peduli/<slug>/`, one per `PINTU`, a thin channel page carrying concept/story + SEO + its program list + roadmap status, but NOT "cara kerja", which lives on the program because it varies per program); the **Jejak & Dampak showcase** `jejak/index.astro` and **jejak detail** `jejak/[slug].astro` (tier `article`, with `Share.astro` + `Lightbox.astro`); **organisasi directory** `organisasi/index.astro` (`/organisasi/`) and **organisasi detail** `organisasi/[slug].astro` (`/organisasi/<slug>/`, dynamic from `getOrganisasiPages()`); the legal pages (`privasi`, `syarat`, `transparansi`); Keystatic admin (`keystatic/`); and the build-time share images `open-graph/[...route].ts` (manual entries plus one per program page, one per organisasi page, and one per jejak, the latter two namespaced `organisasi/<slug>` / `jejak/<slug>` so slugs across programs, organisasi, and jejak can never collide). "Dampak" is not an entity but a computed lens over the `jejak` collection (`src/lib/impact.ts`: `getGlobalImpact`/`getPintuImpact`/`getProgramImpact`, sum-by-label via `aggregateMetrics`); `src/lib/jejak.ts` is the single-source reader for jejak. `src/lib/aksi.ts` and `src/lib/ajakan.ts` are the readers for the `aksi` collection — `getAksiByPintu` feeds the pintu page's "cara ikut" list, `getAjakan` feeds the donation card on both of its mounts, and neither caller branches on a programme slug any more. Mega-menu via `ProgramMenuCategory.astro` + `program-menu.js`.
- **`organisasi` is a lateral entity, not part of the pintu → program → jejak hierarchy.** It represents institutional donors (communities/companies) that give routinely, attached to `jejak` via an optional `jejak.organisasi` relationship that stands independent of `jejak.program` — one organisasi's jejak can span multiple programs (e.g. one under Community Giving, another under Ramadhan Berbagi), and `getOrganisasiImpact` (`impact.ts`) sums metrics across all of them into a single dashboard. `src/lib/organisasi.ts` (`getOrganisasi`/`getOrganisasiPages`) is the single-source reader, mirroring `programs.ts`'s pattern; publish gate is the same as programs (`active` + `detail.description` filled = gets `/organisasi/<slug>/`). `getJejakByOrganisasi` (`jejak.ts`) excludes jejak whose organisasi has been deleted or deactivated from that organisasi's aggregation and history list — but such a jejak still renders and aggregates normally under its `program`/pintu, since organisasi is an optional add-on, not a validity requirement (unlike an orphaned `program` reference, which drops the whole jejak). Not surfaced in the mega-menu or pintu pages — reachable only via `/organisasi/` and any cross-links a page chooses to add.
- **`/jejak/` shapes its feed by how many jejak exist**, so no card is ever left orphaned: 1 renders a single wide card, 2 render two equal cards side by side (throwing the second into a 3-column grid makes it look stranded), 3 to 6 render a wide "terbaru" card plus a compact grid of the rest, and 7 or more switch to archive mode, a uniform grid grouped by month with no featured card at all (month headings already convey recency, and a lone wide card mid-archive breaks the rhythm; the heading is dropped entirely when every jejak falls in one month). All shapes are the same `JejakCard.astro` under `variant="wide" | "stack" | "compact"`, with `titleLevel` dropping to 4 beneath a month heading so the h2 → h3 → h4 order never skips. The inline script owns two filters at once: the pintu chips, and a reveal window of 9 cards (`FEED_REVEAL_STEP`, handed to the DOM via `data-jstep` so the number lives in one place). The window is counted over cards that pass the chip, so switching pintu resets it. Every card is rendered server-side and only its visibility is toggled, which keeps the feed whole for crawlers and for JS-off visitors; for the same reason the "tampilkan lebih banyak" button ships `hidden` and is revealed by the script, since without JS nothing is limited and the button would be a lie.

- **The URL word is not the interface word, on purpose.** Paths read `/peduli/…` while the navigation says "Pintu Berbagi". No single Indonesian prefix is natural across all six purposes — *donasi lingkungan* and *peduli pangan* are both awkward — and a survey of seven Indonesian platforms found none using a verb namespace at all (Rumah Zakat and BAZNAS use `/program/`, BenihBaik and Dompet Dhuafa `/category/`). So the path stays neutral and the phrase each field is actually searched by moves into that page's `title`/`h1` (*Bantuan Pangan*, *Donasi Pendidikan*, *Peduli Lingkungan*). **Do not "fix" this into agreement without reading this note first.** `pintuPath()` in `src/consts.ts` is the only place the URL shape is written; nine files used to assemble it themselves, which is why moving the route once cost nine edits.
- **`/relawan/` and `/logistik/` are site-level, and absent from `NAV_LINKS` on purpose.** Giving time or lending a gudang does not pick a purpose — the same gudang holds food parcels today and disaster relief next week — so neither can be a pintu. They are reachable from the hub and from each pintu's "cara ikut", which is where that intent actually arises, and adding them to a four-item navigation ordered along the donor's trust path would cost more than it returns while they have no programme.
